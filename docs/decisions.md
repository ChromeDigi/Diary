# Decisions

- **Plain HTML/CSS/JS, no build step.** Simple to run, host and change.
- **Entries in localStorage only.** The repo is public, so entries must never touch it. Trade-off: no sync between devices; JSON export/import covers backups.
- **Hosted on GitHub Pages** (https://chromedigi.github.io/Diary/) from `main` / root. Every push deploys.
- **Commits use the GitHub no-reply email** to keep the personal email private.
- **Phase 2 = entry tags** (owner, 2026-10-23): small, no deps, fits localStorage; storage moves to `diary.entries.v2` with v1 kept as a safety net.
- **New purpose: weekly therapy update** (owner, 2026-10-23). Roadmap rewritten around daily check-in → weekly report. Design-first order so every later screen is built once in the new style.
- **Tags folded into Phase 3 check-in as "theme chips"** (2026-10-23). `phases/2-tags.md` is superseded; reuse its migration + test ideas.
- **Charts are hand-made inline SVG** (2026-10-23), keeping the app dependency-free.
- **Aurora glass style + CSS 3D, no libraries** (owner, 2026-10-23, from a live prototype). Remotion ruled out for the UI (video tool, needs Node); could return later for recap videos. Calm mode + reduced motion turn all motion off.
- **UI prefs in `diary.prefs.v1`** (2026-10-23), separate from entries, so prefs never touch the entry schema.
- **Check-in = tap scales 1–5 + mood as 1–5 orbs** (owner, 2026-10-23). Skippable ratings keep weekly charts honest; numbers feed Phase 4. Storage → `diary.entries.v2`, v1 kept.
- **Report notes in `diary.reports.v1`, backup format v2 with reports** (2026-10-23). Notes auto-fill until edited, so the weekly update never starts from scratch. Report code in `report.js` to keep `app.js` readable.
- **Bring-to-therapy items in `diary.talk.v1`; session notes + goal stored with the week in `diary.reports.v1`; backup v3** (2026-10-23). A floating 💬 button makes adding one tap from anywhere.
- **Rewards are derived, never stored** (2026-10-23): totals/badges come from entries, reports and the talk list, so nothing can get out of sync. Only `prefs.palette` and `prefs.fun` are saved. No streaks, by design.
- **Passcode lock = real encryption** (2026-10-23): PBKDF2-SHA-256 (250k) → AES-GCM in `diary.vault.v1`; plain copies (incl. old v1) removed only after the vault is read back and verified. Prefs stay plain (no diary content). No recovery by design; exported backups stay plain JSON.
- **Logo = holographic foil (G), chosen from 9 live previews** (owner, 2026-10-23); plus glowing ring, jelly taps, sliding entries, starfield, count-up. All motion off in calm mode.
- **Therapy Homework Brief becomes the main output** (owner, 2026-10-23), following the owner's existing workflow ([brief-format.md](brief-format.md)). Sleep is entered manually (owner choice: Apple Health can't be read from a web page; export is huge). Skills are logged honestly with a "need review" option. Entries → v3, backup v4.
- **Brief periods = session dates** (owner, 2026-10-23): previous session + 1 → session; first brief 13 days back, start editable. Auto drafts state data only; interpretation is mine to type. Briefs in `diary.briefs.v1`, backup v5.
- **.docx written by hand (`docx.js`: stored ZIP + minimal WordprocessingML)** (owner chose a real .docx, 2026-10-23), keeping the app dependency-free.
- **Health + calendar via an iPhone Shortcut, one tap each morning** (owner, 2026-10-24): web pages can't read HealthKit/Calendar; Shortcuts can. Data travels in the `#` fragment (never sent to a server), then is stripped. Manual edits win over imports. Work events stored per day in `diary.days.v1`.
- **Home Screen diary gets Health data by clipboard** (owner, 2026-10-25): the Home Screen web app's storage is separate from Safari, so the `#health=` link lands in the wrong copy. Moving the diary to Safari was rejected because Safari can clear site data after 7 days unused. The diary starts the Shortcut (`shortcuts://run-shortcut`) and pastes the result; 3 taps instead of 1. The link route stays for Safari.
- **No PC route to Apple Health** (2026-10-25): Health has no Windows app, web access or API; iCloud Health data is end-to-end encrypted. Only the manual "Export All Health Data" zip exists, too heavy for daily use.
